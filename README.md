# 墨锭试磨室

运行：

```bash
npm start
```

访问 `http://localhost:3037`。数据保存在 `data/ink-stick-testing.json`（先写 `.tmp` 再原子替换）。

## 模块分工

- `rules.js` —— 取样规则与耐久卡判定（领域规则）。
- `store.js` —— 档案保存：JSON 原子落盘 + 串行化读-改-写临界区。
- `page.js` —— 页面操作：两个视图（墨锭档案 / 潮箱耐久卡），只读后端结果。
- `server.js` —— HTTP 接入与错误码翻译。
- `seed.js` —— 初始档案（含待读数、已完成、已失效各一张示例卡）。

## 潮箱耐久卡规则

1. 试磨后余墨入潮箱建卡：记录卡号、余墨重量、取样人。余墨 **不足 3 克或已发霉则留待取样，不建卡、不占编号、不留任何记录**（422）。
2. 同一试磨重复建档返回 **409**；重复墨锭编号建档也返回 409。判定与写入在同一临界区内，页面和记录都不会留半截。
3. 满 7 天、满 14 天各记一次色差与起皮；两次必须由**不同的人**记录，**两次都正常**才算耐久合格。未满期不能记，同一节点不能重复记。
4. 原试磨的评分或沉淀被更正后，关联有效卡**立即失效并移出统计**（失效卡不计耐久合格/不合格），旧读数仍在“已失效”列表可查。
5. 列表分为待读数、已完成、已失效三类，可按状态筛选。

## 主要接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET/POST | `/api/items` | 墨锭列表 / 建档（重复编号 409） |
| POST | `/api/items/:code/tests` | 新增试磨记录（评分、沉淀） |
| PATCH | `/api/items/:code` | 更新墨锭状态 |
| POST | `/api/items/:code/tests/:testId/correction` | 更正评分/沉淀，联动失效耐久卡 |
| GET/POST | `/api/cards` | 耐久卡列表（`?status=` 筛选）/ 建卡（422/409） |
| POST | `/api/cards/:id/readings` | 提交 day7 / day14 读数 |
| GET | `/api/cards/:id`、`/api/cards/stats` | 单卡详情 / 统计 |
